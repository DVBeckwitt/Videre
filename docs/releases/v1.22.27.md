Videre 1.22.27 works around an Invidious DASH bug so it no longer causes missing-check-ID playback failures in the Videre frontend.

Some affected Invidious instances return an unsigned DASH URL that fails with HTTP 400: No check ID. Videre now recovers the signed DASH URL from the instance's web player before starting native playback. This is a client compatibility fix for an upstream Invidious issue; it requires no server secrets or server changes.

- Working instances keep their normal API path. Already-signed URLs add no probe, and healthy route checks are remembered briefly to avoid repeated startup requests.
- Affected instances obtain a fresh signed URL while preserving local media proxying. Recovery is attempted once; progressive playback remains the fallback.
- Failed source setup and delayed responses cannot hijack a newer video. Server errors retain retry and instance-switching options without automatic retry loops.

Verified on a Pixel 8 Pro running Android 17 using the actual Videre player and an isolated native test app. Recovered DASH played at 1080p, progressive fallback played at 360p, and a repeated healthy start made no additional resolver requests. First-time checks and recovery still incur network latency; public instance availability varies.
